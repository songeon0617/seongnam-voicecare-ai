# 공식 검색 출시 결함 수정 결과 · 2026-09-07

**판정: 출시 불가 / 개발 종료 불가.** TLS와 원문 처리·비용 보호를 보완했지만, Stage 1 실제 답변 완수는 **6/20(30%)**다. 최종 코드의 저장 응답+실제 HTTPS 재생은 **7/20(35%)**이며 새로운 실제 API 평가가 아니다. 마지막 유료 재검증도 답변을 완수하지 못했다. 이 실패를 수정한 뒤 추가 유료 호출 없이 재생으로만 확인했다.

모든 수치의 문항별 판단과 원기록은 [summary.json](voicecare-evaluation/release-20260907/summary.json)에 있다. `partial_answer`, HTTP 200, 계약 검증 통과만으로 답변 성공을 판정하지 않았다. 같은 개발 에이전트가 원문/표시 내용/고정 평가 요구를 비교한 심사이며 시민 독립 평가가 아니다.

## 1. 시작 상태

`codex/voicecare-official-search`, `8f5436d`, 작업 트리 깨끗함. 기존 보고 수치는 서버 166/166, UI 52/52다. `.env.local`에 키와 `gpt-5.6-terra`가 있었으나 검색 활성화/예산/공유 Redis 설정은 없었다. 비밀값은 기록하지 않았다. 이번 수정은 로컬 미커밋 상태이며 push/Production 변경은 없다. 개발 에이전트 요청과 운영 Terra 모델은 별개다.

## 2. 검색 OFF 206건 원인 분류

다른 원인의 0은 **해당 경로를 실행하지 않았다는 뜻**이다. 숨겨진 TLS 실패 등을 206건 중 일부로 추측해서 나누지 않았다. 별도 실환경 확인에서는 검색/예산 미설정, 중간 인증서 누락, 과거 URL 404, 허용 호스트 밖 검색 결과, 원문 추출/관련성 문제가 실제로 확인됐다.

## 3. TLS 원인 및 해결

Node 24.19.0의 성남시 HTTPS GET은 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`로 실패했다. Windows Schannel 검증을 사용하는 GET은 200이었다. 서버 인증서 발급자는 Sectigo Public Server Authentication CA DV R36이며, 서버가 제공하지 않은 중간 인증서를 보완하자 동일 Node 요청이 200으로 성공했다.

Windows가 검증한 체인의 공개 중간 인증서를 복사하고, Node 기본 Mozilla 루트인 Sectigo Public Server Authentication Root R46의 서명인지 `X509Certificate.checkIssued/verify`로 확인했다. 중간 인증서 SHA-256은 `8C:54:C3:34:B6:6B:A4:E4:26:77:2A:F4:A3:F9:13:6C:19:A1:AE:C7:29:FD:B2:8C:53:5C:07:A5:A4:EF:22:E0`이다.

성남시 허용 URL 전용 요청에만 기본 루트+중간 인증서를 전달한다. `rejectUnauthorized: true`, 호스트명 검증, DNS 검사·주소 고정, 리디렉션 검증을 유지한다. 전역 TLS 변경, leaf 신뢰, 부분 체인 신뢰, 인증 무시는 없다. 인증서 보완 검증/기한 검사도 회귀에 포함했다. Vercel에서의 실제 원문 수집은 미검증이다. [Node TLS 문서](https://nodejs.org/api/tls.html)

## 4. 긴 원문 문제 및 해결

기존 추출기는 문서 전체가 900자를 넘으면 `paragraphs: []`로 만들었다. 현재 런타임은 parse5로 실제 `.content-section`/`main`/`.content-body`를 찾고 실행 코드·숨긴 내용·폼·탐색 영역을 제외한다. 짧은 원문은 그대로 유지하고 긴 문서는 상위 제목 단위로 하위 제목·목록·표 머리글·조건·각주를 묶는다. 구간당 최대 6,000자를 통째로 보존한다. 문서 일부의 금액/자격만 잘라 자유 요약하지 않는다.

일반 HTML 수신 최대 600KB, 실제 2.3MB인 `/sitemap`만 3MB로 제한했다. HTML을 모델에 전송하지 않는다. 검색 출력은 최대 2,400토큰이며 로컬 추출에 별도 모델 호출은 없다. 홈페이지·사이트맵·예약/입력 단계 화면은 발견용 링크로만 쓰며 정책 근거에서 제외한다.

**잔존 한계:** 쪼갤 수 없는 6,000자 초과 구간은 여전히 생략한다. 제목 구조가 빈약한 긴 표에서는 질문에 필요한 위치/신청 조건만 골라 완수하는 능력이 부족하다. 긴 원문 문제가 모든 범주에서 해결됐다는 판정은 하지 않았다.

## 5. 실제 검색 아키텍처와 비용 지점

질문 → 안전/타 지역 guard → 모호한 목적 CLARIFY → 명확한 기존 13개 구조화 안내 우선 → 그 밖의 질문은 OpenAI Responses `web_search` 1회 → 실제 도구 실행·출처 URL 검증 → 공식 HTTPS 원문 수집 → 과거 URL 실패 시 현재 홈페이지/사이트맵에 게시된 공식 링크에서 복구 → 인용의 원문 포함 및 주제 관련성 검사 / 원문 구간 추출 → 출처·대조 시각·미확인 최신성 표시 → 클라이언트 계약 검사.

검색엔진에 남은 `/city/.../contents.do` URL 다수가 현재 404였고, apex URL은 리디렉션 검증에 실패하기도 했다. 임의 URL 치환 없이 현재 사이트의 실제 메뉴를 읽어 여권 안내를 복구했다. 공식 호스트는 기존 두 개를 유지했다. 도서관·폐기물·청년 기관 등의 검증된 별도 도메인 연결은 이번에 확대하지 않았다. 이것은 현재 답변 실패 원인 중 하나다.

과금은 검색 경로의 Responses 모델 입출력 토큰 및 web_search 호출에서 발생한다. 구조화/CLARIFY/원문 fetch/로컬 추출/재생은 앱의 OpenAI 유료 호출이 없다. 기존 의도 라우터와 생성 모듈의 유료 경로는 보존했지만 이번 운영 경로/평가에서는 실행하지 않았다.

문서 30건·5분 캐시와 성공 검색 30건·1분 해시 키 캐시를 사용한다. 원래 확인 시간을 보존하고 캐시 응답의 새 모델 호출/추정 비용은 0이다. 질문 원문을 캐시 키로 저장하지 않는다. Redis 원자 예약 코드는 서버 시간·하루 20회·예약액 최대 $3·동시 1회·2초 간격·소유자 확인 해제를 사용한다. 실패 예약은 환급하지 않는다. **Production/Vercel에 공유 저장소가 없거나 저장소가 실패하면 유료 호출 전에 차단한다.** 저장소 자격 증명/실서비스 원자성 검증은 남았다. 이는 실제 청구액의 계정 하드 상한이 아니다. ## 12. Safe fallback 비율

원 Stage 1 **11/20 = 55%**, 최종 재생 **10/20 = 50%**. 질문에 답하지 않은 partial 1건/3건은 이 비율 밖의 별도 미완수다. fallback은 성공 분자에 넣지 않았다. 종전 검색 OFF 복구는 **206/240 = 85.83%**다.

## 13. Wrong answer / wrong source

확인한 새 정책 사실 생성 0. 원 실평가의 **무관한 답변 근거 2건**(청년 공간→공공데이터, 문화재단→일반 관련사이트)은 보존했다. 재생 중 조사/일반어가 관련성으로 계산되는 추가 오류도 찾아 회귀를 추가했다. 최종 재생에서 확인된 무관한 답변 본문은 0이다. 링크만 반환한 실패의 관련성까지 모두 정상이라고 주장하지 않으며, 공식 URL 형식과 답변 적합성은 구분한다.

## 14. 남은 P0/P1

확인된 잔존 P0는 **0**, 전 주제/새 실검색에서의 P0=0 보증은 미완료다. P1 blocker는 **3개 묶음**으로 남는다.

1. 여러 필수 분야에서 현행 공식 URL/기관 출처를 확보하지 못해 답변을 완수하지 못함.
2. 관련 공식 근거가 있어도 필요한 준비물·위치·이용 조건을 완수하지 못함. 구조가 없는 6,000자 초과 원문 한계도 남음.
3. 분산 비용 보호의 실제 저장소 연결·검증 미완료. Production은 안전하게 호출을 거부하는 상태.

실제 휴대폰 마이크/스피커는 미검증이며 확인된 고장 건수에 임의로 더하지 않았다. P1이 남으므로 출시 완료/개발 종료로 판정하지 않는다.

## 15. 비용 사용량/추정

총 Responses **20회**, web_search **20회**: 초기 실패 1 + Stage 1 검색 18 + 마지막 재검증 1. 입력 247,051토큰, 출력 5,004토큰, 입력 중 캐시 쓰기 9,699/읽기 81,589토큰. Terra Standard의 입력 $2/MTok, 출력 $12/MTok, 캐시 읽기 $0.20/MTok, 쓰기 1.25배, 검색 $0.01/회로 **약 $0.61214**다. 실제 청구 확정액은 확인하지 못했다. [공식 요금](https://developers.openai.com/api/docs/pricing)

기존 20회/$3 예약액 제한을 높이지 않았다. 재생·Stage 2·Stage 3의 추가 유료 호출은 0이다. 원문 HTTPS/호스팅 네트워크 비용은 이 OpenAI 추정액과 별개다. billing/자동충전/운영 환경변수는 변경하지 않았다. [호출별 원장](voicecare-evaluation/release-20260907/paid-ledger.json)

## 16. Production 배포 여부

**미배포.** P1·실답변 기준·공유 비용 검증 조건 미충족으로 main push, Vercel Production 반영, 출시 커밋을 실행하지 않았다. 로컬 수정은 검토할 수 있도록 보존했다.

## 17. 공개 URL 검증 결과

신규 공개 배포가 없으므로 신규 공개 URL 재검증도 미실행이다. 종전 Production의 성공 기록을 이번 수정의 성공으로 인용하지 않는다.

## 18. 실제 휴대폰에서 사용자가 확인할 것

- iPhone Safari / Android Chrome에서 실제 HTTPS 사이트에 접속해 마이크 허용·거부 후 각각 음성/글 입력이 가능한지 확인.
- 실제 발화 “이동수단 알려줘” → 선택 → 후속 질문과 전사문이 맞는지 확인.
- 여권 질문에서 신청 장소·공식 URL·미확인 최신성이 보이고 기본 안내와 “공식 원문 듣기”가 구분되어 들리는지 확인.
- 스피커/블루투스 출력, 읽기 중지, 마이크 시작 시 이전 읽기 중단을 확인.
- 화면 잠금/다른 앱 전환·복귀 시 마이크가 남지 않는지 확인.
- OS 키보드가 열린 상태의 320/390px 상당 화면, 가로 넘침, 선택·전송·듣기 버튼 접근을 확인.

현재 자동화는 320/390px 화면·44px 이상 핵심 버튼·가로 넘침·CLARIFY·음성 mock·원문 듣기를 통과했다. 이를 실기기 PASS로 표기하지 않았다. Production 미배포이므로 현재 공개 사이트로 검사하면 종전 버전을 검사하는 것이다.

## 19. 제출자료 변경 내용

README, 제출 HWPX, 제출용 기술 설명·검증 수치는 **변경하지 않았다**. 검색 확장의 Production 성공 후에만 갱신한다는 사용자 조건을 따랐다. 이번에는 개발 감사 보고서/원기록/로컬 회귀만 추가했다.
