`node scripts/verify-voicecare.mjs`는 lint→typecheck→서버→UI→build를 실행합니다. `node node_modules/@playwright/test/cli.js test competition-flow.spec.ts voice-first.spec.ts --browser=chromium`을 실행하고 `firefox`, `webkit`으로 바꿔 각각 독립 서버에서 확인합니다. 디자인 상태는 `test design-review-capture.spec.ts`로 별도 검사합니다. HTTP 검사는 빌드 후 `node scripts/check-voicecare-legacy-release.mjs`로 실행하며, 결과 폴더는 `VOICECARE_RESULT_DIRECTORY`로 지정합니다.

HTTP 검사의 예전 ‘원문 전체와 답변이 같아야 함’ 조건은 질문별 구조화 응답 계약으로 갱신했습니다. 이 검사는 사실 정확도 점수가 아닙니다. 답변 품질 시나리오는 실제 공식 문서의 조건·금액·연락처를 기대값으로 별도 확인합니다. 수치들은 검사 범위가 겹치므로 합산한 고유 사례 수로 발표하지 않습니다.

390px 홈에서 질문을 가장 먼저 보여 주고 분야 버튼의 중복을 제거했습니다. 보조 메뉴는 입력 아래에 있으며, 화면과 키보드 순서가 일치합니다. 답변 후 큰 음성 재질문 버튼을 한 번 누르면 같은 위치에서 인식을 시작하고, 글자 재질문은 입력란으로 초점을 옮깁니다. 인식 결과는 확인·수정 후 명시적으로 전송합니다. 빠른 메뉴 재개방 후 스크롤 잠금과 음성 결과 확인 직후의 초점 간섭도 회귀 검사로 수정했습니다. 처음으로는 질문·답변·문맥을 초기화하고 홈 음성 버튼으로 초점을 옮깁니다. 사전 검사에서 발견한 직접적인 현재 위험 문장 “지금 자살하려고 해요”도 기존 self-harm 고정 안전 안내로 연결하고, 부정·과거·인용 문맥은 별도 검사했습니다.

기존 공식 원문 확인 기록은 2026-09-09이며 이번 UI 수정 때문에 확인일을 갱신하지 않았습니다. 정책 12건의 게시·수정일은 미확인이며, 복지관 시설 안내 1건만 표시된 수정일을 기준으로 관리합니다. 원문에 없는 요금·서류·자격이나 서로 충돌하는 내용을 확정하지 않습니다. 복지 / 이동·교통 / 건강 / 민원·생활 / 기타는 최대 두 단계의 생활정보 메뉴 안에만 표시합니다. 13개 스냅샷은 내부 자료이며 서비스 전체 범위를 뜻하지 않습니다.
