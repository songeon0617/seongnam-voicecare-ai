## 1. 재현과 수정

수정 전 동일 질문 `이동수단 알려줘`를 로컬과 공개 API에 한 번씩 보냈다. 로컬은 특별교통수단으로 DIRECT 확정했고, 공개 API는 `service_required` 확인 질문이었다. 이 실행에서는 사용자가 보고한 ‘공식자료 없음’ 문구나 timeout을 재현하지 못했다. 실제 음성 전사문은 확보하지 못했으므로 입력 오류라고 단정하지 않았다. 전체 payload/응답은 [변경 전 기록](voicecare-before.json)에 보존했다.

확인한 구조적 문제는 13개 후보에 묶인 의도 라우터, 넓은 교통 질문의 특정 서비스 편향, 선택 버튼의 문맥 초기화였다. 개편 API는 안전·지역·확인을 먼저 처리하고 명확한 기존 서비스만 구조화 안내로 연결한다. 다른 공공 질문은 별도 공식 검색 제공자에 보낸다. 일반 대중교통/차량/비용을 구분하고 번호·짧은 답·모름·새 질문을 처리한다. OFF·한도·시간 초과·공급자 오류·원문 확인 실패를 자료 부재로 표시하지 않는다.

독립 역할 검토 중 긴급 증상 누락, 과거 증상 표현과 현재 위급 상황의 충돌, 지역 관계, 시점 민감 질문의 기존 문서 확정, HTML에서 조건·제목을 분리하는 문제를 발견해 수정했다. React passive effect 정리가 빠른 키보드 마이크 시작을 취소하는 경쟁 상태도 재현했다. 세션과 effect 세대를 확인하는 microtask 정리로 수정했고, 실제 hidden 이벤트는 즉시 취소한다.

긴 구조화 본문은 짧은 소개 뒤에서 펼쳐 본다. 기본 TTS는 화면의 짧은 안내와 일치하고, 전체 듣기는 명시적으로 선택한다. 원문 조건을 잘라 짧은 정책 문장으로 만들지 않으며 긴급 안내는 전체를 유지한다.

## 3. 범위와 공식 출처 정책

현재 바로 안내하는 범위는 질문이 명확한 기존 13개 구조화 서비스이다. 넓은 교통·청년·도서관 질문에는 확인을 제공하며, 그 외 질문은 13개 목록 밖에서도 검색 경로에 도달한다. OFF 상태에서는 새 사실 답변을 완수하지 못한다. 모든 일상 표현과 주제에 대해 확인·답변 완수를 보장하지 않는다.

허용 호스트는 HTTPS `www.seongnam.go.kr`, `seongnam.go.kr` 두 개다. 검색 도구의 도메인 필터는 하위 도메인을 포함하므로 서버에서 정확한 호스트를 다시 검사한다. 게시판·후기·직원목록·로그인·첨부·임의 리디렉션 URL을 제외한다. 산하기관·중앙정부 도메인은 별도 소유·성남 적용 범위 검증 후 확대할 과제다.

AI는 관련 공식 자료 검색 및 발췌 후보를 만든다. 서버는 도구가 실제 확보한 URL의 본문과 인용을 대조한다. 자유로운 정책 요약을 출력하지 않는다. 제목·각주·조건을 잘라내지 않도록 900자 이하의 전체 본문 맥락만 발췌하고 긴 본문은 링크로 남긴다. 이것은 상당수 공식 페이지에서 답변 완수를 막을 수 있는 알려진 P1 제약이다.

게시일·수정일·시행기간·신청기간은 확인하지 못하면 null/미확인이다. 대조 시각은 정책 유효일이 아니다. 개인 자격·현재 모집/오늘 운영·진단·개인정보 조회·실제 접수·민간 평가는 확정하지 않는다.

대표 근거는 [평가 설계](voicecare-evaluation-design.md)와 고정 데이터의 14개 원문(기존 13개 및 성남시 여권 안내 `https://www.seongnam.go.kr/cn02040801`)에 기록했다. 다른 분야의 정답 근거는 미완성이다. ‘미확인’과 ‘자료가 없음’을 구분했다. 문서 캐시는 최대 30건·5분이며 원래 확인일을 보존한다. 갱신 시 URL·적용 지역·대상/조건/날짜 관계를 원문으로 다시 확인하고 변경된 문서는 회귀 사례와 함께 수정해야 한다.

## 4. 제공자·모델·설정·보호

제공자는 OpenAI Responses API의 `web_search`, 기존 운영 모델은 `gpt-5.6-terra`다. 개발 에이전트 모델과 별개이며 운영 모델을 교체하지 않았다. 변수 이름은 `OPENAI_API_KEY`, `OPENAI_MODEL`, `PUBLIC_INFORMATION_WEB_SEARCH_ENABLED`, `PUBLIC_INFORMATION_SEARCH_DAILY_USD`다. `PUBLIC_INFORMATION_AI_ENABLED`는 보존한 종전 의도 라우터 비교에 쓰인다. 비밀값은 기록하지 않았다.

검색 기본 OFF/일일 예산 기본 0, 호출당 도구 최대 1회, 출력 2,400토큰, 파이프라인 25초, UI 30초, 자동 재시도 없음. 검색 동시 1건·최소 간격 2초·UTC 하루 최대 20건·예상액 $0.15/호출 예약을 구현했다. 실패 예약을 되돌려 반복 과금을 허용하지 않는다. HTTP 제한은 프로세스당 분당 30건·동시 3건이다. 이 제한은 분산 인스턴스의 공유 지출 상한이 아니고 실제 청구를 강제 제한하지도 않는다. 계정 결제·자동충전·한도는 변경하지 않았다.

질문/문맥은 외부 AI로 전송될 수 있다. 번호·이메일·사용자 URL을 일부 가리지만 이름·상세 주소 등 모든 개인정보를 제거하지 못한다. 질문·음성을 앱 DB에 저장하지 않으며, 이것을 외부 제공자의 무보관 보증으로 설명하지 않는다. 원문 캐시는 개인정보로 보이는 내용과 명단을 제외한다. 검색/출력 길이·도메인·DNS·리디렉션·클라이언트 위조 응답 검사는 오프라인으로 검증했다. TLS 확인은 우회하지 않았다.

| 자유입력 확인 | 일부 확인에서 버튼 없음 | 모름/새 질문 제공. 확인 루프 회피 |
| 유효하지만 미등록인 공공 질문 | 기존 미지원/등록 자료 없음 | 공식 검색 또는 원인별 복구. 13개는 범위 상한 아님 |
| UI 검색 timeout | 15초 | 검색·원문 서버 25초보다 긴 30초. 지연/취소 검사는 유지 |
| 첫 화면 개인정보 | 종전 AI 라우터 처리 문구 | 질문·최소 문맥의 외부 웹 검색 처리 및 가림 한계 표시 |
| 예시/음성의 명확한 질문 | 종전 라우터의 복수 후보 가능 | 새 경로가 선택한 단일 공식 문서의 전체 원문·출처 검증 유지 |
| 긴 본문 표시/기본 TTS | 처음부터 전체 원문 | 짧은 안내 우선, 상세 펼침 후 전체 표시·명시적 전체 듣기. §5의 요구에 맞춤 |
| HTML 악성 문구, 지역·안전·가짜 출처 | 실행/오안내 금지 | 그대로 유지. 원문 전체 대조와 상태 위조 방어 추가 |

원문 확인이 없는 새 정책 내용을 새로운 정답으로 만들지 않았다. 기존 61개 데이터는 덮어쓰지 않았다.

이전 로컬 기준 SHA는 `ec472bbe20cc89af536bc63957662f47cb79cc88`이다. `codex/voicecare-official-search` 브랜치에 별도 저장한다. 최종 로컬 커밋은 이 보고서 전달 메시지와 `git log`로 확인할 수 있다. main으로 push하지 않았고 새 Vercel 프로젝트도 만들지 않았다.

GitHub 배포 기록의 마지막 성공은 deployment 6293107300, SHA `bc86f88d869723e3f173b37850570b711ce31314`, 2026-09-06T12:48:22Z이다. 공개 주소는 [기존 VoiceCare](https://seongnam-voicecare-ai.vercel.app), 해당 배포 기록 URL은 [Vercel 배포](https://seongnam-voicecare-o6uq5g7te-seongnam-voice-care-ai.vercel.app)이다. 공개 별칭이 그 SHA를 가리킨다는 별도 Vercel 인증 확인은 하지 못했다. 이 값은 신규 배포 SHA가 아니다.

비상 조치는 기존 프로젝트에서 `PUBLIC_INFORMATION_WEB_SEARCH_ENABLED=false`, `PUBLIC_INFORMATION_SEARCH_DAILY_USD=0`을 적용하고 새 배포/환경 반영을 확인하는 것이다. 향후 배포 후 핵심 회귀가 생기면 Vercel의 검증된 이전 배포를 선택해 롤백하고 공개 URL의 SHA와 필수 시나리오를 다시 검사해야 한다. 이번에는 배포하지 않아 운영 롤백도 실행하지 않았다. 로컬 비교는 원본 브랜치/기준 커밋의 별도 checkout에서 가능하며 작업물을 강제 reset하지 않는다.

## 9. 제출자료

기존 `docs/submission-2026/` 원본·서명·개인정보는 보존했다. 별도 `voicecare-revision-20260907/`에 MD/TXT·변경 적용표·HWPX·PDF를 만들었다. 팀명은 Astra이고 공식 예선 양식의 항목 순서를 유지했다. 한글 네이티브 저장·PDF 변환 결과 **6쪽**이며 본문 휴먼명조 13pt/160%와 페이지 잘림을 다시 검사했다. 종전 ‘7쪽’ 수치를 복사하지 않았다. 최종 검토 기록은 이 폴더의 `native-render.json`, `format-qa.json`이다.

개편 미배포, 실검색 평가 미완료, 제한된 발췌, 운영 비용 한계, TLS 문제를 원고에 반영했다. 서명이나 참가 자격 확인을 만들지 않았고 이미 보낸 문의와 제출 이메일을 다시 보내지 않았다. 해당 폴더는 개인정보 공개 방지를 위해 Git에서 제외했다.

## 10. 사용자에게 남는 일

현재 추가 결제나 설정 변경은 필요하지 않다. 코드·보고서·별도 제출 검토본을 검토할 수 있다. 실제 기기가 있는 경우 [이용 가이드](voicecare-user-guide.md)의 iPhone/Android 마이크·스피커·키보드 확인표를 수행해야 한다. 참가 자격 문의 답변, 신청서의 개인정보·서명, 최종 제출은 사용자가 확인한다. 검색 활성화와 실평가·배포는 이번 범위에 포함하지 않으며, 향후 별도 결정 후 미해결 출시 조건부터 충족해야 한다.
