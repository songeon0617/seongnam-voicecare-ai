### 새 응답과 재현 검증의 구분

첫 수정 배포 `e0d060d288f8df7c336d31b4ba168baed595e34c`에서 기존 20문항을 공개 Production API로 전부 새 실행했습니다. 구조화 응답 2건·길찾기 미지원 1건은 모델을 호출하지 않았고, 17건에서 실제 새 모델·검색 도구 호출이 확인됐습니다. 전부 HTTP 200·스키마 통과였지만 이는 의미 정확성 PASS와 다릅니다.

의미 검수: 핵심 완수 13/20, 안전한 PARTIAL 3/20(음식물·전입·상담료), UNSUPPORTED 1/20(길찾기), 잘못되거나 오래된 근거 3/20(여권 장소·공연·문화재단). 실패를 제외하거나 과거 성공 응답으로 대체하지 않았습니다. 원본은 `production-live-summary.json`입니다.

이후 필터 수정은 과거 모델 출력 + 현재 HTTPS 원문 20건 재생과 실제 새 응답에서 문제가 된 3개 후보 URL을 강제로 넣는 합성 제공자 재현(`observed-risk-replay.json`)으로 검사했습니다. 두 검증은 **새 모델 호출이 0회**입니다. 재현 3건에서 잘못된 출처가 제외되고 올바른 접수 장소/다가오는 무료 공연/문화재단 예매 안내까지 확보됐습니다. 중간 재생 `replay-post-fix-summary.json`에서 금연 질문의 취업상담 링크를 추가 발견해 제거했고, 최종 재생은 `replay-verified-summary.json`입니다. 재현 중간의 안전성만 확인한 결과도 `observed-risk-replay-initial.json`에 보존하며 최종 완수 결과와 구분합니다.

최종 원문 재생: **핵심 완수 16/20, 안전한 PARTIAL 3, UNSUPPORTED 1, 관찰된 잘못된 근거 0**. 전체 최초 새 모델 검증에서 발견한 잘못된 근거 3건을 지우고 0건으로 바꾼 수치가 아닙니다. 문항별 판단은 `semantic-review.json`에 기록했습니다.
