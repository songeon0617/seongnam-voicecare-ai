## 2. STT 방식

클라이언트에서 `SpeechRecognition` 또는 `webkitSpeechRecognition`을 탐지한다. 사용자 마이크 버튼 클릭으로만 `ko-KR`, `continuous=false`, `interimResults=true` 인식을 시작한다. 기기 마이크를 별도의 MediaRecorder/getUserMedia로 중복 점유하지 않는다.

중간 결과는 화면 미리보기만 제공하고, 세션 종료 시 확정 텍스트를 입력란과 기존 POST API에 한 번 전달한다. 결과 문자열에 추가 정책/사실을 붙이지 않는다. 300자를 넘으면 원문을 자르지 않고 수정 후 제출하도록 안내한다.

HTTPS/localhost 조건, 지원 여부, 권한 거부, 마이크 연결 실패, 네트워크/인식 오류, 시작 예외, 결과 없는 종료, 사용자 취소, 30초 대기 제한을 처리한다. 취소/입력 수정/예시 선택 이후 늦은 콜백을 무시한다. 음성 실패로 텍스트 기능을 비활성화하지 않는다.

## 3. TTS 방식

사용자가 답변 듣기를 누를 때 `speechSynthesis.speak(new SpeechSynthesisUtterance(...))`를 실행한다. 서버가 반환하고 화면에 표시한 `answer.plainLanguageSummary`만 읽으며 자동 재생하지 않는다.

한국어 음성을 선택하고 기기 내 음성을 우선한다. `voiceschanged` 및 버튼 클릭 시 음성 목록을 확인한다. 한국어 음성이 없으면 다른 언어로 읽지 않고 재시도/한국어 음성 설치를 안내한다.

긴 본문은 최대 160 Unicode code point 단위로 가능하면 공백에서 나눈다. 모든 발화 조각을 합치면 원문과 정확히 같으며 원문 순서를 보존한다. 발화 종료 후 다음 조각을 읽는다. 45초 동안 종료/오류 이벤트가 없는 조각은 실패 안내로 복구한다.

중지·새 텍스트 입력·질문 제출·마이크 시작·예시 선택·컴포넌트 해제 시 이전 음성을 cancel한다. 출처/확인 상태는 기존 화면에 유지하며 듣기 버튼 근처에 본문만 읽는다는 범위를 표시한다.

## 4. 브라우저 호환성

| 기능 | 지원 판단과 제약 |
| --- | --- |
| STT | 표준/접두사 생성자 존재와 보안 연결을 실행 시 확인한다. 지원이 제한적이고 브라우저 서비스/정책/권한에 따라 실패할 수 있다. 특정 브라우저 이름만으로 작동을 보장하지 않는다. |
| TTS | 폭넓게 지원되지만 한국어 음성의 설치 여부와 품질은 OS/브라우저별로 다르다. |
| 미지원 | 안내 후 기존 텍스트 질문·답변을 그대로 제공한다. |

[MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)은 일부 브라우저(예: Chrome)가 서버 기반 인식을 사용한다고 설명한다. 따라서 브라우저 내장 API를 사용해도 음성이 브라우저 제공자의 서비스로 전송될 수 있고 오프라인을 보장하지 않는다. 이 내용을 마이크 설명에도 표시했다. 앱 자체의 별도 음성 API/서버/키는 추가하지 않았다.

[MDN SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis), [voiceschanged](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event)를 참고했다. 기기 내 한국어 음성이 없으면 원격 한국어 음성이 선택될 수 있다.

## 5. 접근성

- 기존 input/form의 키보드 제출과 로딩/오류/빈 결과 상태를 유지한다.
- 마이크/듣기/중지는 실제 button이며 Tab/Enter/Space를 사용할 수 있다.
- 마이크 상태는 색상과 명시적 텍스트, aria-label 및 aria-pressed로 전달한다.
- 기존 role=status 영역에서 짧은 상태를 전달하고 중간 인식 문자열은 live 낭독하지 않는다.
- TTS 자동 재생을 하지 않는다. 읽는 동안 상태 영역은 aria-live=off, 종료/오류/중지 후 polite로 복원한다. 화면의 전체 답변을 live 영역으로 만들지 않는다.
- 실제 스크린리더를 끄거나 감지하지 않는다. 실제 스크린리더와의 음성 겹침은 제품별 수동 검증이 필요하다.

## 6. 테스트

최종 `npm test`: **72/72 통과**.

- 서버 기존 테스트: 42/42
- Chromium UI: 30/30 (기존 텍스트/안전 표시 9건 + 음성 21건)

음성 테스트는 표준/접두사 STT, 확정 결과 입력/기존 API 연결과 중복 방지, 출처 URL/확인일/최신성, 미지원/보안 연결/시작 예외/권한/마이크/네트워크/무음 오류, 취소/늦은 콜백, 미확정 종료/시간 제한, 긴 질문 수정, 한국어 TTS 원문 전체 일치, 자동 재생 없음, 재생 중 live 상태, 중지/입력/마이크/예시/제출 시 취소, 음성 지연 로드, 미지원/오류/무응답 복구를 검증한다.

STT/TTS 브라우저 API는 모두 mock이다. 일부 테스트는 실제 로컬 검색 API를 호출하지만 테스트 서버의 OpenAI 기능은 비활성화되어 있다. 실제 마이크 입력, 외부 브라우저 인식 서비스, 스피커 발음/음질, 실기기 스크린리더 동작은 검증하지 않았다.

## 8. 데모 시나리오

지원 브라우저/기기에서 마이크 클릭 → 권한 허용 → “장애인 콜택시 이용하려면 어떻게 해야 해?” → 확정 질문 자동 제출 → 공식 답변/출처 표시 → 답변 듣기 → 중지 → 새 질문으로 이전 재생 중지를 시연할 수 있다.

오인식은 입력란에서 수정 후 질문하기로 다시 제출한다. 음성 인식 서비스 실패나 권한 거부 시에도 예시 질문/텍스트 제출로 데모를 이어간다. OpenAI 기능 비활성 상태에서도 공식 원문 안내와 TTS 흐름을 사용할 수 있다.

## 9. 남은 위험

- 실제 음성 인식 서비스 지원·네트워크·권한·인식률 미검증. API 생성자가 있다고 서비스 연결이 보장되지는 않는다.
- 한국어 음성 미설치, 원격 음성 로드 지연, 브라우저 발화 중단/음질 편차가 있을 수 있다.
- TTS는 서버 문자열을 바꾸지 않지만 숫자·전화번호·금액의 발음 정확성을 보장하지 않는다. 화면의 원문과 출처를 함께 확인해야 한다.
- 소음이나 스피커/스크린리더 소리가 마이크에 들어가 오인식될 수 있다. STT 확정 후 자동 제출하므로 사용자가 인식 질문을 확인하고 수정할 수 있도록 안내한다.
- 기존 공식 데이터 4건/키워드 검색/최신성 및 프로세스 단위 API 제한의 한계는 유지된다. 실제 OpenAI smoke test는 기존처럼 설정 부재로 미검증 상태다.

## 10. 다음 단계

대회에서 사용할 브라우저·마이크·스피커·네트워크에서 한국어 인식/발음/긴 답변 재생과 권한 거부 후 텍스트 복구를 직접 확인한다. 한국어 음성을 미리 설치하고 필요하면 헤드셋으로 소리 되먹임을 줄인다. 이후 실제 스크린리더에서 버튼 조작/상태 안내/중지를 확인한다.

외부 음성 API, embedding/Vector DB, 인증, 대규모 리팩터링은 추가하지 않았다.
