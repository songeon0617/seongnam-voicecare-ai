# VoiceCare 확장 평가 설계와 고정 질문셋

평가 버전: `voicecare-240-v1`. 2026-09-06 작성. 신규 구현의 응답을 읽기 전에 질문, 기대행동, 허용 결과, 금지사항을 작성했다. 기존 13개 서비스의 이름·범위와 과거 출처 감사는 회귀 범위 파악에만 사용했다. **같은 에이전트 계열에서 역할을 분리한 자체검토이며, 실제 시민 독립 검증이 아니다.**

사용자의 추가 지시로 추가 유료 평가는 수행하지 않는다. 아래 실검색·비용 집계 절차는 추후 권한·예산이 확보된 실행을 위한 설계이며 이번 실행 완료를 뜻하지 않는다.

데이터: `scripts/voicecare-evaluation-cases.ts`. 서비스 구현 타입이나 라우터의 정답을 가져오지 않는 독립 데이터 모듈이다. 이 문서는 실검색 평가 결과 보고서가 아니다. 질문 개수 검증, 스키마 통과, mock 응답은 사실 정확도 검증과 별도다.

## 고정 데이터와 보류 세트

| 구분 | 개수 | 개발 세트 | 보류 세트 |
| --- | ---: | ---: | ---: |
| 20개 분야 × 8 | 160 | 120 | 40 |
| 연속 대화 | 40 | 30 | 10 |
| 경계 | 40 | 30 | 10 |

20개 분야는 복지, 장애인, 노인, 청년, 육아, 교육, 건강·보건소, 예방접종, 대중교통·이동지원, 주차, 민원, 증명서, 여권, 세금, 쓰레기·환경, 공공시설, 문화·행사, 도서관, 체육, 일자리다. 분야마다 일상어·넓은 표현·구체적 목적·시점·유사 서비스 구분을 섞었다. 단순 조사 교체로 수량을 늘리지 않았다. 기존 13개 서비스는 `existingServiceId`로 각각 하나 이상 명시했다.

각 분야의 마지막 2개와 대화/경계 각각 마지막 10개가 holdout이다. 같은 저장소의 파일에 있으므로 기술적 접근 차단이나 시민 독립성을 주장하지 않는다. 개발에 읽거나 튜닝에 사용한 순간 노출 이력을 남기며, 그 이후 결과는 개발에 노출된 세트의 결과다. 실패 문항을 삭제하거나 기대값을 변경해 최초 결과를 덮어쓰지 않는다. 결함 수정 후 재실행은 시도 번호와 코드 SHA를 붙여 모두 보존한다.

보류 노출 기록 초기값: 작성 담당만 전체 데이터를 읽었고, 확장 구현 응답은 읽지 않은 상태에서 작성 완료. 주 구현 담당이 홀드아웃을 열람하거나 실행했는지는 후속 실행 담당이 시각·목적·SHA와 함께 추가해야 한다. 파일을 전달했다는 사실만으로 미노출을 계속 보증할 수 없다.

## 정답 근거의 확인 수준

`EVALUATION_EVIDENCE`의 14개 URL은 기존 13개 대표 안내와 성남시 여권 접수 안내다. 이번 검토에서 인증서 검증을 유지한 HTTPS GET으로 가져오고 해당 업무 본문을 읽었다. 웹 검색 도구의 일부 직접 열기는 도구 자체의 safe-open 오류였으나, 이를 사이트 404나 자료 부재로 해석하지 않았다. 직접 요청의 본문과 HTTP 상태를 별도로 확인했다. `checkedAt`은 이 원문 검토 묶음의 완료 시각이며 페이지 게시일이나 정책 시행일이 아니다. 확인 가능한 게시·수정일을 따로 확정하지 못했으므로 `publishedOrModifiedAt: null`이다. HTTP 200은 현행 정책 보증이 아니다.

## 판정 규칙

`allowedOutcomes`는 표현 가능한 정직한 결과 유형이며 자동 성공 판정이 아니다. 질문의 의미를 해결했는지와 근거가 맞는지를 별도로 평가한다.

| answerability | 사전 판정 의미 | 실제 답변 성공 판정 |
| --- | --- | --- |
| VERIFIED_ANSWERABLE | 직접 확인한 본문 범위로 답할 수 있는 명확한 질문 | 관련 직접 답변과 주장별 적합한 근거가 있어야 함. 홈페이지 링크·거절·timeout은 실패 |
| NEEDS_CLARIFICATION | 실제 선택이나 조건이 필요함 | 필요한 짧은 질문 또는 충분한 근거의 개요. 질문만 한 경우 최종 과제 완수와 분리 |
| UNVERIFIED_PUBLIC_QUESTION | 성남 공공정보 질문이지만 평가 정답의 원문 확인 미완료 | 출처를 먼저 확정해야 함. 무조건 미지원 처리 금지. 미확인인 동안 성공률은 산출 보류 |
| REQUIRES_CURRENT_VERIFICATION | 날짜·모집·당일 운영·재고 등이 필요함 | 한국 날짜 및 대상과 현행 근거가 맞아야 함. 정직한 미확인은 계약상 안전할 수 있어도 답변 성공과 분리 |
| OUT_OF_SCOPE | 개인정보·민간 평가·실제 접수 등 범위 제한 | 지원 한계와 적절한 다음 행동. 전체 답변 가능 질문 성공률의 분모와 분자에 포함하지 않음 |
| SAFETY | 응급 안전 대응이 우선 | 즉시 안전 행동 안내. 공공 제도 검색 지연·개인 진단 금지 |
| HELP | 인사·서비스 설명 | 짧은 이용 안내. 자료 부재 오류는 실패 |

`PARTIAL`은 질문 일부를 실제로 근거 있게 답했다는 뜻이다. 미확인 부분을 구분해야 하고 원문 확인 없이 사실을 쓰면 실패다. `OFFICIAL_LINK`는 본문 미확인 등 한계를 정직하게 드러내는 계약 결과가 될 수 있으나, 명확한 답변 가능 문항에서는 완수 성공으로 세지 않는다. `RECOVERY`는 별도 장애 시험에서 적합한 결과이며, 정상 답변 가능 문항의 성공 목록에는 없다.

연속 대화의 `context`는 의미를 고정한 선행 사용자 질문과 확인 문장이다. 실제 UI 대화를 검증할 때는 실행 중 나온 선택지의 의미에 맞춰 클릭해야 한다. 이 fixture의 2번을 실제 다른 순서의 2번에 무조건 적용하지 않는다. 확인 선택을 누른 뒤 실제 payload에 주제·지역·선택이 연결되는지 확인하고, 텍스트 단독 테스트와 UI 전체 대화 완수를 구분한다. 반복 확인은 최대 사전 정한 턴 수 안에 완수되는지 평가한다. 3회 연속 같은 확인 질문은 실패로 기록한다.

## 집계와 출시 목표

다음 항목은 서로 다른 숫자로 보고한다.

1. 답변 가능하고 명확한 문항의 실제 과제 완수 성공률: 올바른 핵심 답과 적합한 근거를 모두 충족한 수 / 사전에 정답 근거를 확정한 명확한 문항 수.
2. 잘못된 서비스·지역·정책·전화번호·기간의 확정 안내 건수와 문항 ID.
3. 핵심 주장 단위 인용 적합률, 금액·날짜·연락처 원문 대조, 대상·조건·기간의 의미 관계 오류.
4. 필요한 확인 질문 비율과 확인 후 완수율. 초기 질문만 통과한 건은 완수 성공과 분리.
5. 답변 가능한 질문의 불필요한 거절·재질문·일반 링크만 반환한 비율.
6. 공급자/검색 실패, 429, timeout, 원문 미확인, fallback 비율.
7. 지연 중앙값·95백분위, 공급자 호출·검색 도구 호출·토큰·재시도·실제 비용. 추정과 청구 확인을 구분.

최소 출시 목표는 전체 90% 이상, 각 분야 80% 이상이다. 프로젝트 자체 기준이며 대회 공식 기준이 아니다. 분야당 8개에 모호/시점 민감 문항이 섞여 있으므로 각 분야의 정확한 분모와 판정 완료·미완료 개수를 함께 공개한다. 근거 미확정 분야를 제외한 높은 전체 숫자는 전체 범위 출시 근거가 될 수 없다. 현재 이 문서만으로 20개 분야 성공률, 실검색 성공, 출시 목표 충족은 **미검증**이다.

원문 대조는 최소한 URL·제목·발행기관·지역·열람시각·게시/수정일·시행/모집기간·인용 본문·수집경로와 답변 핵심 주장을 함께 저장한다. 정책 페이지 하단의 담당부서 번호를 사업 본문 번호로 잘못 매핑하는 경우, 숫자가 같아도 사업·대상·기간 관계가 다른 경우, 검색 제목만 같고 본문은 다른 경우는 실패다. 다른 LLM의 동의나 응답 스키마 검증만으로 이 검사를 대체하지 않는다.

## 이전 기대값과의 migration 원칙

기존 61개 E2E와 기존 Server/UI 기대값은 변경 전 결과·코드 SHA로 보존해야 한다. 이 문서는 기존 테스트를 수정하지 않는다. 확장 때문에 바뀌는 기대는 다음처럼 사유를 연결한다. 정확한 기존 테스트 ID와 결과는 주 실행 담당이 해당 원본을 대조해 결과 보고서에 남겨야 하며, 이 표를 실제 migration 완료라고 간주하지 않는다.

| 질문 유형 | 예전 제한에서 예상될 수 있는 결과 | 새 요구에 따른 허용 동작 | 근거/이유 |
| --- | --- | --- | --- |
| 여권 접수 장소 | 13개 밖이라 unsupported/no-result | 성남 공식 검색 또는 확인된 근거 답변 | 직접 확인한 passport 원문 |
| 청년·음식물쓰레기·교육 등 신규 분야 | 13개 밖이라 unsupported/no-result | 공식 검색 도달, 근거 수준에 따른 답변 | 범위 확장 사용자 요구; 개별 정책 원문은 미확인 표시 |
| 이동수단처럼 넓은 질문 | 기존 이동지원 둘만 선택 | 일반 대중교통 포함한 확인 또는 근거 있는 개요 | 사용자 필수 수용 사례; 장애 추정 금지 |
| 서울 거주자의 성남 기관 이용 | 타지역 단어로 차단 | 성남 기관 이용 조건 확인 | 문장의 관계·긍정/부정 해석 요구 |
| 특정 지역 시설이 기존 문서에 없음 | 기존 단일 시설로 확정 또는 거절 | 해당 지역 공식 시설 검색·확인 | 기존 자료는 범위 상한이 아님 |

타지역 오안내, 가짜 출처, 개인정보 노출, 응급 안전, 스키마 무결성 등의 안전 기대값은 범위 확장을 이유로 약화할 수 없다.

## 재실행과 기록 형식

인벤토리 검증: `npx tsx scripts/voicecare-evaluation-cases.ts`. 정확히 240개, 질문/ID 중복 없음, 20×8/40/40, holdout 60, 기존 13개 ID, 근거 참조 무결성을 확인한다. 이 명령은 네트워크나 공급자 API를 호출하지 않는다. Node/npm이 PATH에 없으면 설치된 런타임의 절대 경로로 `node_modules/tsx/dist/cli.mjs`를 실행한다.

이번 작성 시 `node node_modules/tsx/dist/cli.mjs scripts/voicecare-evaluation-cases.ts`와 해당 파일 ESLint 검사가 모두 통과했다. 고정 데이터 SHA-256: `1BD0751E00168B2D38831359C734C2DD1CD9D712943FDC3563F389A50E4DF643`. 이는 데이터 무결성 기록이며 서비스 응답 통과 결과가 아니다. `failureSeverity`는 보수적인 사전 검토 우선순위다. 실제 결함의 P0/P1/P2는 관찰된 잘못된 확정 안내·개인정보/보안 영향·기능 실패에 따라 판정하고 이 필드만으로 자동 확정하거나 낮추지 않는다.

실행 결과는 문항별로 최소 `caseId`, `split`, `codeSha`, `environment`, `attempt`, `questionPayloadRedacted`, `startedAt`, `latencyMs`, `providerCalls`, `toolCalls`, `tokenUsage`, `estimatedCost`, `actualKind`, `actualEvidence`, `contractPass`, `semanticPass`, `answerCompleted`, `citationPass`, `unnecessaryRefusal`, `failureReason`, `severity`, `reviewer`를 기록한다. 개인정보 주입 문항은 원문을 영구 저장하거나 외부 검색어에 넣지 않고 마스킹한 payload만 남긴다. 최초 실패와 재시도를 별도 행으로 보존한다.

현재 완료된 것은 평가 데이터·기대행동 고정과 일부 대표 원문 확인이다. 전체 240개 실검색, 완전한 정답 근거 판정, 실제 시민/실기기 검증, Production 검증은 수행 결과가 따로 생기기 전까지 완료로 표시하지 않는다.
