## 2. 발견된 문제

- 실제 Production에서 `부천시 노인맞춤돌봄서비스 신청하는 곳 알려주세요`가 keyword DIRECT로 성남시 신청처·전화번호를 반환했다.
- 기존 대표 공식 출처 13개 중 8개가 현재 HTTP 404였다. 검색엔진에는 구형 페이지 내용이 남아 있었다.
- 새 공식 페이지에서 일부 담당 전화번호와 대상 설명이 변경되어 있었다. 보장구 안내는 본문/하단 전화번호가 서로 달랐다.
- 공약 이행 완료를 근거로 버스요금 자료를 current로 표시했지만 현재 정책 최신성을 보증할 수 없었다.
- 데이터 대조 후 기존 복수 서비스 테스트에서, 명시적으로 언급한 서비스가 검색 top-K 밖으로 밀리면 단일 DIRECT가 될 수 있음을 확인했다.
- 보안 헤더 없음. deprecated 표현 생성 모듈은 공개 API에서 호출되지 않으며 일부 타입·검증 도우미 및 회귀 테스트가 연결되어 있다.

## 4. 실제 수정한 문제

타 지역을 키워드·AI·fallback 전에 UNSUPPORTED로 종료하고 사실·출처를 비웠다. 직전 확인 문맥도 검사한다. 성남시·분당구·수정구·중원구 및 지역 미지정의 기존 경로는 유지했다. 일반어와 지명 접미사를 혼동하는 회귀를 검사했다.

출처 이관 때문에 종합 안내가 여러 공식 페이지로 분리된 경우 선택적 `supportingSources`를 추가하여 기존 출처 카드에서 추가 근거를 열 수 있게 했다. 서비스 ID/개수/route 계약을 유지했다. 링크는 HTTPS로 검증하고 AI가 만들지 않는다.

새 근거에 없는 건강관리 제외 조건·무료 단정을 제거하고, 바뀐 담당 문의를 대조했다. 버스요금 안내는 PDF에서 실제 사업 페이지로 교체했으며 current를 unknown으로 낮췄다. 보장구 원문의 연락처 충돌은 감추지 않고 표시한다.

추가 실제 질문에서 분당구 장애인 이동지원은 AI DIRECT(특별교통수단), 성남시 돌봄은 keyword DIRECT, 서울시·청주시는 guard UNSUPPORTED(출처 0개)였다. 공개 응답의 보안 헤더 적용도 확인했다. 실제 마이크·스피커·브라우저 권한을 통한 음성 품질은 행사 기기에서 수동 확인해야 한다.

문서 전용 후속 커밋은 위 검증 코드와 실행 파일이 같음을 git diff로 확인하고, 그 새 Production 배포 성공 및 대표 sentinel을 재확인한다. 반복 전체 모델 평가로 성공 사례를 골라내지 않는다.

## 18. 현재 경쟁 등급

**수상권.** 구현 완성도와 안전 설계는 본선에서 경쟁할 근거가 있다. 현재 증거만으로 우승권이라고 단정하지 않는다. 사용자 편익·지역 수요·독립 평가가 있는 경쟁작보다 불리할 수 있다. 이 등급은 참가작 순위나 합격 확률을 확인한 결과가 아니다.

## 19. 우승권 강점

실제 작동하는 공개 서비스, 오류 시 안전한 종료, 공식 근거 추적, 음성/텍스트 대체 경로, 회귀 검증을 설계 논리로 설명할 수 있다. 타 지역 잘못된 연락처 사례를 재현하고 코드로 차단한 것은 막연한 환각 방지 주장보다 강한 증거다. 출처 404를 찾아 이관하고 최신성을 임의 승격하지 않은 것도 운영 현실을 보여준다.

핵심 메시지는 **“제도명을 몰라도 필요한 공식 안내에 도달하도록 돕고, 애매하면 확인하며, 확인할 수 없는 범위에서는 정책 사실을 만들지 않습니다.”**가 적합하다. ‘틀리지 않는 AI’는 라우팅·원문 오류 가능성 때문에 피한다. 제공한 후보 메시지는 문제의식은 좋지만 ‘틀리지 않게’가 무오류 보증으로 들리지 않게 바꿔야 한다.

## 20. 남은 약점

13개 범위는 PoC로 설명 가능하지만 실서비스 포괄성은 낮다. 최신성 unknown 12개, 일부 공식 원문의 상충 정보, 실제 고령자·시각장애인 검증 부재, 긴 원문과 시각적인 출처 확인 흐름, 키워드 대비 AI 효과의 외부 검증 부재가 남는다. 마이크 버튼 자체는 차별점이 아니다. 거부가 많다는 사실만으로 안전성이나 사용자 가치가 증명되지 않는다.

## 21. AI 기술성 최종 평가

AI는 제도명이 없는 상황 설명에서 허용 서비스 ID와 의도, DIRECT/CLARIFY/UNSUPPORTED, 고정 clarification ID를 선택한다. 사실 본문·연락처·서류·자격은 생성하지 않는다. 명확한 제도명, 출처 매핑, 지역 검사, 거리 제한, 입력 검증은 규칙으로 처리한다.

[키워드 비교 기록](final-keyword-baseline.json): 같은 기존 54개 중 DIRECT 대상 46개에서 검색 top-1이 38개를 맞췄다(82.6%). AI를 끄고 동일 guard와 보수적 fallback을 유지한 전체 계약은 21/54 통과, 실제 모델 사용은 54/54였다. 두 숫자는 서로 다른 지표다. 앞의 검색 후보 적중률과 뒤의 route·후보 집합·확인 질문 계약을 같은 정확도로 비교하면 안 된다. 강하게 튜닝한 별도 규칙 엔진을 이겼다는 실험도 아니다.

- A 설명 강화: AI는 검색의 존재 이유가 아니라 의도 분류와 확인 질문 선택을 보완한다. Structured Outputs는 출력 형식 제약이지 올바른 판단 보증이 아니다.
- B 작은 보완: 독립 질문셋/AI 켬·끔 비교/지연·불필요한 질문 측정은 점수에 실질적 도움이 된다. 이번 코드 보완은 지역·복수 후보의 결정론적 안전 경계에 한정했다.
- C 추가하면 위험: RAG/생성형 답변/위치 엔진을 기술 이름을 늘리기 위해 넣는 것. 데이터 유지·평가 문제가 해결되지 않은 채 공격면과 오류 경로를 늘린다.

‘AI가 약하다’는 질문의 위험은 높지만 역할 크기보다 문제 적합성과 검증 증거로 방어할 수 있다. 새 알고리즘을 개발했다고 주장하지 않는다.

## 22. 성남 지역성 평가

성남 공식 URL, 실제 서비스별 적용 대상, 3개 구, 분당 시설·중원 치매센터의 제한이 코드와 데이터에 반영되어 있다. 다만 문서가 성남 것이라는 사실과 성남 시민의 요구를 조사했다는 주장은 다르다. 홈페이지 정보 분산이나 음성 편익을 지역 사용자에게 확인한 기록은 아직 없다.

## 28. 추가 개발 필요 여부

추가 기능 개발은 필요하지 않다. 새로운 안전성 blocker나 실제 사용자 과제 실패가 확인될 때만 좁게 수정한다. 데이터의 대량 추가도 필수는 아니며 등록 자료의 정확성과 대표 과제에서의 편익을 우선한다.

## 29. 개발 종료 가능 여부

현재 범위의 기능 개발을 종료하고 코드 동결이 가능하다. 배포 후 확인과 실기기 음성·사용자 증거는 개발 완료와 별개의 제출 준비다. 무오류·실서비스 완료 선언은 하지 않는다.
